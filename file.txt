Implement Part 7: Decision Memory Engine.

Current Status:

* Foundation Layer complete.
* AI Infrastructure complete.
* Repository Intelligence complete.
* Monaco Workspace complete.
* Explain My Codebase complete.
* Visual Graph Engine complete.

Objective:

Build a Decision Memory system that records and retrieves the reasoning behind code changes and architectural decisions.

This system should become the long-term memory of the codebase.

Do not implement Intent Mode yet.

Requirements:

1. Decision Memory Domain

Create a dedicated Decision Memory module.

Store information about:

* Why code was added
* Why code was modified
* Why code was removed
* Performance optimizations
* Architectural decisions
* Refactoring decisions
* Bug-fix decisions

The focus is reasoning, not code storage.

2. Decision Record Model

Each decision should support:

* Unique ID
* Title
* Description
* Decision Type
* Reason
* Trade-offs
* Expected Benefits
* Risks
* Author
* Timestamp

Relationships:

* Files
* Components
* Symbols
* Routes
* Modules

3. Repository Linking

Connect decisions to repository intelligence.

Allow decisions to be attached to:

* File paths
* Functions
* Components
* Classes
* Routes

Support multiple decisions per entity.

4. Decision Retrieval Engine

Create retrieval services that answer:

* Why does this exist?
* Why was this changed?
* What decisions affect this component?
* What performance optimizations exist here?
* What architectural decisions affect this module?

5. Decision Timeline

Maintain historical decision chains.

Support:

* Original decision
* Follow-up decision
* Replaced decision
* Superseded decision

Track evolution of reasoning.

6. Decision APIs

Create endpoints:

POST /api/v1/decisions
GET /api/v1/decisions
GET /api/v1/decisions/:id
GET /api/v1/decisions/entity
GET /api/v1/decisions/history

Support filtering by:

* File
* Symbol
* Component
* Route
* Type

7. Frontend Decision Workspace

Create a dedicated Decision Memory panel.

Display:

* Decision title
* Reason
* Trade-offs
* Benefits
* Risks
* Linked entities

Support navigation to:

* Monaco Editor
* Graph Workspace
* Explain Panel

8. Explain Integration

When explaining code:

Include:

* Related decisions
* Architectural rationale
* Optimization rationale

Explanations should become richer when decision memory exists.

9. Graph Integration

Graph nodes should display:

* Decision count
* Linked decisions

Users should be able to open decision details directly from graph nodes.

10. Storage Layer

Create an abstraction layer.

Initial implementation may use:

* PostgreSQL
* Neon

Design for future expansion.

11. AI Support

Use Groq only for:

* Decision summarization
* Decision categorization
* Decision search enhancement

Do not auto-generate decisions.

Decisions should originate from users or accepted workflows.

12. Important Constraints

Do not implement:

* Intent Mode
* AI Code Editing
* AI Refactoring
* AI Patch Generation

Focus only on memory and reasoning history.

Goal:

The system should be able to answer:

* Why was this written?
* Why was this optimized?
* Why was this architecture chosen?
* What reasoning led to this implementation?

even months after the original author is gone.
