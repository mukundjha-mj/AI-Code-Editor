Implement Part 5: Explain My Codebase Engine.

Current Status:

* Foundation Layer complete.
* AI Infrastructure complete.
* Repository Intelligence Engine complete.
* Monaco Workspace complete.
* Groq integration architecture exists.
* Repository metadata is available.
* AST parsing and dependency graph exist.

Objective:

Build the first real AI-powered feature:

Explain My Codebase.

The system should explain code using repository intelligence + AI.

Do not implement code modification features yet.

Requirements:

1. Explanation Service

Create a dedicated explanation engine.

The explanation engine must use:

* Repository metadata
* Symbol index
* Dependency graph
* Component relationships
* Route metadata
* Context retrieval layer
* Groq AI infrastructure

The LLM should not receive raw repository dumps.

Always provide structured repository context.

2. Explanation Types

Support:

* File explanation
* Component explanation
* Function explanation
* Class explanation
* Module explanation
* Route explanation

Each explanation type should have its own strategy.

3. Repository Context Builder

Build context assembly logic.

Collect:

* Selected file
* Related files
* Imports
* Exports
* Dependencies
* Consumers
* Parent components
* Child components

Limit context intelligently.

Avoid sending unnecessary files.

4. Explanation API

Create endpoints:

POST /api/v1/explain/file
POST /api/v1/explain/component
POST /api/v1/explain/function
POST /api/v1/explain/module
POST /api/v1/explain/route

Input should identify the selected entity.

Response should contain:

* Summary
* Responsibilities
* Dependencies
* Relationships
* Risks
* Suggested reading order

5. Frontend Explain Panel

Create a dedicated explain panel.

User can:

* Select file
* Select symbol
* Request explanation

Display:

* Summary
* Dependencies
* Related files
* AI explanation

Panel should work beside Monaco Editor.

6. Symbol Awareness

Allow users to:

* Click component
* Click function
* Click class

Trigger explanation for the selected symbol.

Use repository intelligence data.

7. Explanation Caching

Cache explanations.

Cache key should include:

* File path
* Symbol
* File modification state

Prevent repeated AI calls.

8. Explanation Modes

Support:

* Quick Explain
* Deep Explain

Quick:

* Fast
* Limited context

Deep:

* More context
* Cross-file reasoning

9. Streaming

Use Groq streaming support.

Display explanation progressively.

10. Important Constraints

Do not implement:

* Intent Mode
* Code Editing AI
* Code Generation
* Decision Memory
* Architecture Graph UI
* AI Refactoring

Focus only on understanding and explaining.

Goal:

The user should be able to click any file, component, class, route, or function and immediately understand:

* What it does
* Why it exists
* How it connects to the system
* What depends on it
* What could break if it changes

using repository intelligence combined with Groq-powered reasoning.
